# Threat model (Phase 0)

- **Updated:** 2026-10-09, end of Phase 0. Review at the end of every phase.
- **Scope:** what exists in Phase 0: the proxy, the `createAction` wrapper, the database roles and
  row-level security, configuration and secrets, the browser surface, and the CI supply chain. There is
  no sign-in, no feature action and no upload yet.

STRIDE: **S**poofing, **T**ampering, **R**epudiation, **I**nformation disclosure, **D**enial of service,
**E**levation of privilege.

## Assets

Workspace data (boards, tasks, comments), user identities, the database credentials of both roles,
`ENCRYPTION_KEY`, the audit trail, and the integrity of what CI builds and deploys.

## Trust boundaries

Browser → Vercel (proxy, then pages and Server Actions) → Postgres as `trask_app`. Developer machine and
GitHub Actions → Postgres as `trask_migrator`. npm registry and GitHub Actions marketplace → build.

## Accepted trade-offs

- `style-src 'unsafe-inline'` (above). Revisit if the UI stops needing runtime inline styles.
- Cookie-presence check in the proxy: validating sessions there would mean a database call on every
  request including static files. Real validation happens in `requireAuth()` (Phase 1).
- RLS is workspace isolation only; roles are enforced in the application.

## Open items going into Phase 1

- Widen the wrapped-action test to every `"use server"` file; keep `brandAction` private to
  `create-action.ts`.
- Lowercase `workspaceId` before the role lookup and the context, so rate-limit or cache keys cannot
  split on letter case.
- Decide `User` table protection; lowercase emails.
- Run `scripts/verify-db-roles.ts` against Neon `dev` and `main`.
- First CI run: WebKit E2E, the Postgres service, the Windows Git Bash hook, the Docker init path.
- E2E rows for `/sign-in?next=...` pin 404 because the page does not exist; flip them to 200 when
  Phase 1 builds it.
- `/_next/image` redirects private app paths to sign-in; set `images.localPatterns` when private
  images exist. `/robots.txt` also redirects to sign-in until it is allowlisted.
- Member service (Phase 10): check the target member's current role before changing it, and refuse to
  remove or demote the last OWNER. `canAssignRole` alone does not do either.
- CI housekeeping: `cancel-in-progress` also cancels runs on `main`; the Postgres image tag appears in
  `ci.yml` (twice) and `docker-compose.yml`; the E2E job builds twice (Playwright builds again).
